# Readout engine qualification and numerical amendment

Initial qualification job **3196205** exercised both actual 650M readout models for four optimizer updates, comparing uninterrupted training against a stop at update 2 before scheduled validation, then restart and two more optimizer updates. Four GH200 GPUs, the pinned SIF, nine global pairs with uneven rank accumulation, 11 short training pairs and eight validation pairs were used. These disposable checkpoints are never candidates or production initializations.

CLS-MLP passed bitwise comparison of model, optimizer, RNG, sampling/training state and validation predictions. Residue-MLP failed. The [failure log](../logs/readout-qualification-3196205.log) and [diagnostics](readout-resume-failure-diagnostics.json) are retained. Its update-2 model/optimizer and predictions were exactly identical. At update 3, the uninterrupted/resumed gradient norms were 5.912360191345215 and 5.912360668182373. Parameter differences were initially at most 2.98e-8; by update 4, the maximum parameter difference was 8.49e-6 and maximum orientation-logit difference was 0.000732421875. The tiny eight-pair validation set changed rank metrics, so treating the original run as exact would have been incorrect.

The amendment sets `gradient_as_bucket_view=False` in a separate `readout-code/train.py`. Original scripts and the immutable adaptation release remain intact. DDP bucket rebuilding can change tensor storage offsets. A [GPU diagnostic](gradient-storage-offset-diagnostic.json) found that identical values with different offsets can produce different norm reductions, including the 128-element output-head shape. This is consistent with the observed clipping-roundoff divergence; the original run did not record every intermediate gradient, so a complete kernel-level causal trace is not claimed. PyTorch documents related limits in its [numerical accuracy notes](https://github.com/pytorch/pytorch/blob/main/docs/source/notes/numerical_accuracy.md).

Independent per-parameter gradient storage avoids dependence on bucket offsets at clipping and optimizer steps. Its additional storage is 2,600,228,360 bytes per GPU, approximately 2.42 GiB. Architecture, loss, parameter groups, AdamW settings, precision, batches, learning-rate schedule, checkpoint contents and data are unchanged. An AST qualification requires this one DDP keyword to be the only executable trainer change, and hashes require the other four core modules to be byte-identical to the original release.

Replacement qualification job **3196606** repeats the full interrupted/resumed comparison for both actual-size heads. Production freezing requires [its report](readout-aligned-ddp.json), both bitwise comparison reports, and the [minimal-change check](readout-engine-amendment.json) to pass. No tolerance is substituted for bitwise equality. Passing this controlled case supports resumability on the pinned software and hardware; it is not a universal guarantee across different GPU architectures, PyTorch releases or every possible future workload. The amended and original trainers are not asserted to follow identical numerical trajectories for all heads.

The previously qualified full-length model computation is unchanged. Short-input distributed memory increases from about 19.7 to 22.2 GiB per GPU, within the 95.6 GiB visible GPU capacity. The new wrapper tests cover budget stopping, failed workers, real local signals with mocked scheduling, manual stops and error handling. Existing checkpoint corruption/fallback and historical scheduler-requeue evidence are preserved with their original scope.
