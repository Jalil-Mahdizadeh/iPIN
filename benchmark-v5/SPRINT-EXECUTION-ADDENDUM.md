# SPRINT execution optimization

The unchanged native HSP constructor completed on all 16,132 TRAIN+TEST sequences. Native serial scoring then accumulated a complete 16,132 × 16,132 score matrix, although the benchmark only requests pairs within 3,022 test sequences. Its observed speed would require roughly another one to two hours for all 350,382 TRAIN edges.

A local copy of the pinned native serial scoring source now skips only unused destination entries. After the original `PtoHSP` constructor has completed **all native high-count marking, HSP splitting, score calculation and sorting on the full corpus**, each source protein's destination vector is stably restricted to endpoints present in the candidate files. Source protein IDs, graph edges and order, retained HSP values and order, the scoring expression, floating-point type, symmetry assignments and final length normalizers are unchanged. No threshold, length limit or sequence is changed. The installed SIF and external upstream source remain unchanged.

Why the requested scores are preserved: an update to an unrequested matrix entry never feeds into a requested entry. The native update reads only that entry's prior accumulator and the two HSP records, then mirrors the result to its reverse. Retaining both endpoints of every requested pair therefore retains every contribution to that pair. Stable filtering retains the exact sequence of floating-point additions for each requested cell, including self-pairs. Full-corpus high-count preprocessing must precede filtering; pruning the input HSP file instead would not provide this guarantee and is not used.

Qualification used the complete native HSP file and all 16,132 sequences, a deterministic 1,017-edge subset of the actual TRAIN-positive graph, and 304 candidate rows covering test identities, directly observed TRAIN edges, reverse duplicates and self-pairs. All 304 output lines were **byte-identical** to the unmodified native binary; 293 scores were nonzero. Source copies, compiled binary, fixtures, outputs and hashes are recorded in `qualification/sprint-requested/qualification.json`. The compiler flags match the native serial build (`g++ -O3 -Wall`, no OpenMP or fast-math). Only the added stable destination-filtering block differs from the pinned sources.

Production still uses all 350,382 TRAIN-positive edges, every requested test pair, native default hyperparameters, and serial accumulation. This is a documented execution optimization of the native algorithm, not retraining or a different predictor. It was introduced after neural results were known, before SPRINT test scores were inspected, to reduce redundant computation. The original full-matrix attempt is stopped only after the qualified implementation completes successfully. Its logs are retained.
