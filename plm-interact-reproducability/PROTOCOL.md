This is an inference reproducibility check of the published PLM-interact paper (Nature Communications, DOI [10.1038/s41467-025-64512-w](https://doi.org/10.1038/s41467-025-64512-w)). It uses the supplied ARM64 SIF and released frozen checkpoints. **No retraining, optimizer steps, checkpoint selection, calibration fitting, or threshold fitting is performed.**

The primary evaluation choices were recorded in `provenance/evaluation-plan.json` before large-scale inference. Figure 2 uses all 242,000 released cross-species test rows and the humanV11 checkpoint. Figure 4 uses all 52,048 released Bernett test rows and its separate checkpoint. Figure 5 uses the released 841-case human mutation test set and evaluates the paper's 598-case comparison subset separately. Both the authors' mutation-fine-tuned checkpoint and the humanV11 zero-shot checkpoint are evaluated without changing their parameters.

The paper, all supplementary figures/tables, reporting summary, peer review, and source workbook are preserved under `../literature/plm-interact/`. Original release metadata and file hashes are under `provenance/`. The publication's Zenodo archive is also preserved. Its model computations are identical to the inspected current upstream source; the relevant inference-file change is `strict=False` to `strict=True` checkpoint loading. This workflow requires strict loading and checks equality of every loaded tensor.

The SIF is `../images/plm-interact/plm-interact-native-arm64-v1.sif`, SHA-256 `e064e38053d6dfcacc65a23467d97f75f79ca6095e6f760def4125ccf452ffc2`. The checkpoints' expected SHA-256 hashes are enforced in `scripts/native_model.py`. Dataset/model revisions are pinned rather than resolving a changing `main` during the experiment. HumanV11 is supplied inside the image; the other two weights were downloaded from the authors' Hugging Face repositories.

Inference preserves the released order within each protein pair. It constructs the ESM2 architecture from the local configuration and then strictly loads all checkpoint tensors, including the unused MLM head. The encoder reads `[CLS] sequence A [EOS] sequence B [EOS]`; the classifier applies ReLU to the CLS embedding and a linear scalar head. The tokenizer's padding token is set to EOS, matching upstream. Padding is masked. Both model and input computations use FP32; AMP and TF32 are disabled. Gradients are disabled and the models remain in evaluation mode. No input sequences are fetched or altered during inference.

Cross-species inputs use a 1,603-token cap, which truncates **zero** released pairs. The prespecified primary Bernett and mutation evaluations retain full sequences. The longest Bernett input is 7,426 tokens, and the longest wild/mutant input is 3,833 tokens, including three special tokens. Separate sensitivity runs use longest-first truncation at 1,603 tokens (the public CLI default) and 2,196 tokens (2,193 residues plus special tokens, motivated by the stated Bernett training limit). Only affected rows are rerun; unchanged rows are merged from the full-sequence run. These alternative settings are reported explicitly, not used to select a best result. The three literal `.` symbols in the released mutation sequences are preserved as supported ESM vocabulary tokens.

For ordinary PPIs, the saved score is `sigmoid(logit)` computed in FP32, as in the upstream inference method. Primary AUPR means scikit-learn **average precision**, matching the authors' evaluation function; trapezoidal PR-AUC is also reported. Raw-logit and float64-sigmoid average precision are recorded to expose ranking ties introduced by FP32 probabilities. AUROC uses the same saved score. Precision, recall, F1, MCC, and confusion matrices use a fixed probability threshold of 0.5 (`>=` is positive). No threshold is selected using the test labels.

For mutation prediction, the released code uses `sigmoid(mutant_logit - wild_logit)`. The paper's equation instead specifies `log(p_mutant / p_wild)`, with `p = sigmoid(logit)`. Both are calculated from the same frozen-model outputs. The latter is evaluated stably in float64 as `logsigmoid(mutant_logit) - logsigmoid(wild_logit)` with zero as the classification threshold. They have the same classification direction but can rank mutations differently. Raw wild and mutant logits are retained so either definition can be independently reconstructed.

Figure 5 samples are joined to the released test set using their mutation and interaction metadata, including accessions, effect label, mutation description, publication, and interaction accession. The workbook has nine mutation ranges converted by Excel into date serials. Those are matched only when all other metadata uniquely agree and the decoded date matches the released range. Every such normalization is recorded; inference uses the original released CSV strings. The resulting 598 rows equal exactly the subset where each individual wild, mutant, and partner protein is at most 2,000 residues. The full 841-case results are never substituted for the published subset.

Cross-species source rows are bound to the released input sequences using the publisher's supplementary identity CSVs. Apparent accession mismatches between PLM-interact and baseline files are resolved by comparing actual sequences; the unordered sequence/label multisets agree. Original row multiplicities are retained to reproduce the published metric, and duplicate counts are recorded. Bernett source rows are matched by their ordered UniProt pair and label. In the final aggregation, every prediction file is checksum-verified, all expected ranks must be present, row IDs must be unique, labels must agree, and no test row may be omitted or added.

Before the main run, the inference implementation was compared against the actual upstream model class on varied-length fixtures, including the longest mouse pair. Batched logits were bitwise equal. Singleton-vs-batched and fixed-vs-dynamic padding checks passed; independent small tests check metric definitions and the mutation formula distinction. Qualification and performance evidence are in `results/qualification.json`.

SLURM job 3110591 uses eight GH200 GPUs across two nodes for cross-species and Bernett evaluation. Work is divided by original row IDs after sorting by length; batch size changes only to control memory. The interactive allocation 3085063 evaluates the mutation benchmarks. Each worker records its GPU UUID, configuration, software versions, checkpoint hash, elapsed time, and output hash. No distributed sampler padding is used, avoiding artificial duplicate predictions. Supplementary pair-order sensitivity uses every 53rd original row (4,568 pairs total), selected independently of labels or predictions; the full deposited reverse-order results are audited separately.

Deposited baseline scores are recomputed independently, but baseline models are not rerun. Training ablations are audited from their supplied scores; they are not retrained. The supplied MMseqs identity annotations are used as published, without recomputing alignments. Mutation train/validation files, if present, are used only for a read-only split-overlap audit and are never passed to inference or training. Structure-generation examples and training reproducibility are outside this checkpoint-only check. The virus-host section is limited to inspecting the published aggregate table; its workbook sheet supplies a summary and training sequences, not held-out prediction scores, so this workflow does not claim an independent Figure 7 metric reproduction or generate viral binding predictions.

A post-hoc Bernett diagnostic was added after the prespecified runs: score disagreements began abruptly above roughly 3,570 tokens, although rounded aggregate metrics already agreed. Caps 3,569–3,573 were probed on the boundary rows and three longest inputs. A cap was accepted only if it uniquely matched every probe's deposited probability within 2e-5; labels and AP were not used to choose it. The unique matching cap, 3,570, was then applied to all 520 affected rows, while the other 51,528 rows reused primary full-sequence predictions. This is a reconstruction of an apparent missing inference setting from published scores, not a prespecified evaluation. Its outputs and all rejected probes are separate; the original primary predictions and metrics remain unchanged. The diagnostic ran on the interactive GPU and is documented in `results/bernett-cap-diagnostic.json`.

All deviations or residual disagreements are described in `REPORT.md`. Successful checkpoint inference reproduces a released predictor's outputs; it does not by itself establish independent retraining reproducibility, experimental biological validity, or generalization beyond these benchmarks.
