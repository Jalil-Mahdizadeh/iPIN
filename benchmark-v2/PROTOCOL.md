**Benchmark v2 fixed checkpoint comparison**

This benchmark evaluates the existing best checkpoint from each of the four completed v2 runs: reference update 4,000, length capped update 8,000, positive weight 10 update 4,000, and clean BCE update 4,000. Selection follows each run's prespecified maximum pooled validation AP over all 13 evaluations. All four are included at the user's request. Checkpoint identities, full hashes, configurations and selection time are fixed in `provenance/selection.json` before new test inference.

Comparators are the released native Bernett model and the v1 reference update 4,000 and symmetric update 7,000. The v1 selections remain unchanged after their jobs stopped. Reuse their benchmark-v1 predictions after verifying checkpoint identity, input arrays, prediction hashes, complete row/label coverage, original inference manifests and protocol compatibility. Recompute comparative metrics and paired uncertainty across all seven models; do not repeat native/v1 GPU inference when these checks pass.

Evaluate the complete author-released Bernett test set: 52,048 pairs, 26,024 positives, 26,024 sampled unreported interactions. The test set has already been inspected in earlier work and informed subsequent research decisions. This is an exploratory historical comparison, not independent prospective confirmation. Use full sequences with no length exclusions or truncation; the longest test input is 7,426 tokens.

The shared inference protocol matches benchmark-v1: the supplied ARM64 SIF, FP32 weights, BF16 autocast, efficient attention, TF32 disabled, clean sequences, both pair orientations and the arithmetic mean of their logits. AP and AUROC use raw pooled logits, and Brier uses the sigmoid of that pooled score. Inference is four deterministic GPU shards with length sorting, token budget 16,384, at most eight physical pairs per microbatch, and atomic 512-row prediction chunks. A common forward implementation is numerically qualified against the frozen v2 trainer using validation pairs. It is valid for these four standard-attention CLS-linear models; no later architecture template is included.

The primary endpoint is pooled test AP for all seven fixed models. AUROC and Brier are secondary. Report each v2 model against native and against both v1 models, retain all results, and include comparisons between v2 interventions and the v2 reference. Report all pairwise differences in the machine-readable outputs. Do not choose another checkpoint, tune hyperparameters, recalibrate probabilities, or alter selection using the test outcomes.

For each model, report precision, recall, F1 and MCC at probability 0.5 and at the maximum-F1 threshold chosen solely from its saved validation predictions on the same 59,258 pairs. Exact F1 ties select the highest threshold. Freeze pooled validation thresholds before new test inference. Original-order inference is a secondary view of the same predictions, not another model selection.

Prespecified length strata are combined residues ≤2,193 versus >2,193, corresponding to input tokens ≤2,196 versus >2,196. Report coverage and prevalence as well as metrics for both strata. Strata use the globally validation-selected checkpoints; there is no stratum-specific reselection.

Uncertainty uses 1,000 paired protein bootstrap replicates with seed 20260929, matching benchmark-v1. Resample unique test proteins with replacement; pair weights are the products of distinct endpoint multiplicities, with one multiplicity for a self-pair. Apply identical weights to every model. Report 95% percentile intervals for pooled AP/AUROC/Brier and their paired differences. These intervals condition on the observed graph and selected checkpoints; they exclude training-seed, remote-homology and model-selection uncertainty. Multiple comparisons are descriptive and not multiplicity-adjusted confirmatory tests.

One four-GPU SLURM job performs inference for only the four v2 models. Each worker has an exclusive lock and commits hashed chunks atomically. Resubmission of the same frozen command verifies and reuses completed chunks with the same configuration and shard count. Final merging requires every expected row exactly once, matching labels, finite logits and matching hashes. No model fitting occurs.
