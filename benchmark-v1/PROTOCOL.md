**Benchmark-v1: interim validation-selected Bernett comparison**

This protocol is fixed before test inference. The benchmark compares reference-seed2 update 4,000, symmetric-seed2 update 7,000, and the authors' released PLM-interact-650M-Leakage-Free-Dataset checkpoint. The two retrained checkpoints were selected by their existing validation rules, with no test-based choice. Their committed files are pinned independently of training retention. Selection time, hashes, run contracts and source provenance are preserved in `provenance/selection.json`. These are best-so-far snapshots, not the final products of the still-running five-epoch training.

The primary dataset is the complete author-released Bernett test set: 52,048 pairs, 26,024 positives and 26,024 sampled unreported interactions. Prepared test rows are unchanged from the original release. All sequences are retained at full length, without truncation; the longest test input is 7,426 tokens. Training and validation homology exclusions are documented in the copied prepared manifest. The historical test set has already been studied during native-checkpoint reproduction and is not a newly prospective holdout.

All three models use the same qualified ESM forward implementation, FP32 weights, BF16 autocast, memory-efficient attention, disabled TF32, tokenizer vocabulary, complete input sequences and adaptive batching. This matches the current retraining validation compute setting. No gradients, fitting or parameter updates occur. A validation-only qualification compares native efficient attention with the original eager attention in FP32, compares BF16 with FP32, checks tokenization and the longest validation input, and checks retrained weights against their saved validation predictions. Numerical differences from the earlier native FP32 reproduction are reported explicitly.

The main comparison gives every model the same inference rule: arithmetic mean of A–B and B–A logits, followed by sigmoid when probabilities are required. AP and AUROC use raw logits to avoid sigmoid-induced ties. This separates improvements in the training objective from improvements obtained merely by pooling at inference. Original-order native and reference results are secondary views of the same models. The paper's Bernett scores used original-order inference; the earlier reproduction also identified an apparent 3,570-token inference cap. Those published and FP32 reproduction results are context and are not substituted for the common full-length, pooled comparison.

Report AP (the authors' implementation of AUPR), AUROC, Brier score, precision, recall, F1 and MCC. Report the fixed probability threshold 0.5 and a model/view-specific maximum-F1 threshold chosen only on the frozen validation set. Use the copied selected-checkpoint validation logits for the retrained models and fresh inference on the same 59,258 validation pairs for the native model. Ties in validation F1 select the highest threshold. Do not tune thresholds or calibrate probabilities on test labels.

Length analyses are specified in advance: combined residues at most 2,193 (at most 2,196 tokens) versus longer pairs. Report coverage, prevalence and metrics separately; do not drop long pairs or select the most favorable stratum.

Uncertainty uses 1,000 paired protein-level multiplier bootstrap replicates, seed 20260929. Resample unique test protein identities with replacement; each pair receives the product of the counts for its two distinct proteins, or one count for a self-pair. Apply the same weights to every model in each replicate. Report percentile intervals for pooled metrics and paired differences. This approximates dependence from repeated protein identities conditional on the observed interaction graph; it does not capture training-seed variation, remote-homology dependence or uncertainty from model selection. Ordinary independent-pair intervals would overstate the effective independence of these data.

Inference uses a separate four-GPU Slurm allocation, leaving both training jobs unchanged. Each worker commits hashed chunks atomically; the same command can resume with the same configuration and shard count. Every merged prediction must have exactly one valid row per expected test/validation pair, matching labels, finite logits, and matching hashes. The report is a benchmark of fixed interim snapshots. Results must not be used to change the current training protocol or choose subsequent checkpoints on test performance.
